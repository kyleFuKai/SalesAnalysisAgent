## 二、三个必写进正式实现的发现

### 发现 1：System Prompt 必须注入当前日期（P0，已验证的修法）

首测 T2 失败：问"上个月"模型反问"哪年哪月"——**模型不知道今天几号**，相对时间无法换算。
修法（spike 中已验证）：System Prompt 末尾追加 `今天是 2026-09-22。` 后，"上个月"被正确解析为 2026-08。
正式 SalesAgent 的 System Prompt 模板**必须含日期占位符**，每请求动态注入。

### 发现 2：权限边界必须逐类写死，模糊表述会导致自相矛盾（P0）

实测同一天、同一用户的两轮对话：
- T2 轮："华东区卖了多少" → **拒绝**（"您作为销售员，只能查询您本人的业绩数据"）
- T4 轮：拒答李明后主动**提出**"我可以帮您查询华东区整体情况"

原因：spike 提示词只写了"不能查其他销售员"，**没写大区汇总是否可行**，模型两轮各选了一种解释。
正式 System Prompt 的权限规则必须按需求 4.4 矩阵**逐类枚举**（本人 ✅ / 他人 ❌ / 本区汇总 ❌ / 跨区 ❌ / 产品维度收窄规则……），不给模型自由裁量空间。

### 发现 3：延迟离需求目标有距离（P1，开优化项）

| 场景 | 实测首 token | 需求 7.1 目标 |
| --- | --- | --- |
| 纯文本流式 | ≈ 5.0s | （简单查询整体 3s 内） |
| 流式 + 工具调用 | ≈ 32s | （多步 15s 内） |

注：实测经 VPN + 智谱公网接口，网络成分大；且 spike 用 `@Value` 注册的 flash 档模型。
**缓解路径**（进正式实现的待办）：① System Prompt 精简（本轮 spike 提示词较长，token 越多越慢）② 高频问题走 Redis 缓存（架构 4.3 本来就有）③ 评估 glm-4-plus 与 flash 的速度/质量差 ④ 上线前在网络直连环境复测，区分网络延迟与推理延迟。

## 三、意外收获

- **拒答发生在工具调用之前**（`toolsInvoked` 为空）——说明提示词层防线真实有效，不是靠 Service 层兜底拦下来的。双保险设计的"第一道"可信。
- 身份冒充的拒答质量高："当前系统登录用户是张伟……任何自称是其他销售员的查询请求都无法通过身份验证"——没有出现需求担心的"技术上不能答"式生硬话术。
- `AiServices` 手工装配（比 @AiService 注解透明）在 spike 场景很好用，正式实现仍按架构用 @AiService，但排查问题时可退回手工装配对照。

## 四、运维小坑（备忘）

- 后台 `mvn spring-boot:run` 被停止时**只杀了 mvn 外壳，Java 子进程残留**继续占端口（本次 8088 被 PID 23348 占用导致二次启动失败）。用 `netstat -ano | grep :8088` + `taskkill //F //PID` 清理。IDEA 里跑不受影响。
- Windows bash 里 curl 传中文参数会按 GBK 编码变成乱码，模型收到的是乱码问题——**用 UTF-8 文件 + `-d @file` 传参**（`printf '中文' > q.txt`），spike 的 curl 命令都已按此写法。
