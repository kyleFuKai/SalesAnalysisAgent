# 销售数据分析 Agent 前端

当前进度：开发计划第 0–8 步（含图表、会话管理和自动化回归）。

## 启动

要求 Node.js 20.19+ 或 22.12+。在本目录执行：

```powershell
npm install
npm run dev
npm run test
npm run build
```

Vite 默认提供本地开发地址；通过代理把 `/auth`、`/agent` 发往 `http://localhost:8080`。后端端口不同时，在本目录创建 `.env.local`，设置 `VITE_DEV_BACKEND_URL=http://localhost:实际端口`，参考 `.env.example`。此变量只能放非敏感 URL，不能放密码或 API Key。

后端配置文件已开启 `app.auth.enabled: true`；**修改配置后要重启后端进程**，否则正在运行的旧进程仍按旧值工作。重启前先核对后端当前的 `spring.sql.init.mode: never`，并按后端 README 完成账号表迁移；不要在共享库上运行测试数据脚本。先启动后端及其数据库，再在登录页使用已有销售员 ID 和密码。前端请求把登录返回的 token 放在 `Authorization` 请求头；token 只在内存里，刷新页面会要求重新登录。

联调时可先无 token 请求 `/agent/chat`：认证生效后应返回 401；若仍返回 403，检查后端是否仍是旧进程或被其他配置覆盖。登录后再用受权限允许的提问验证同步问答链路。

## 当前能力与边界

- `/chat` 可按当前登录角色显示示例问题；默认使用 `POST /agent/chat/stream` 逐步显示回答，也可以手动切换到 `/agent/chat` 同步问答；新建对话会换一个会话 ID。
- 流式模式只有收到 `done` 才标记成功。`error` 事件、连接中断、没有 `done` 都保留已收到的部分文本并显示失败。缓存命中时可能一次返回整段文本，这也按流式协议处理。
- “停止接收”仅中止浏览器继续读流，不保证后端取消模型执行；停止后建议新建对话再问，避免本地显示与后端记忆不一致。
- `CHART_JSON:` 会在完整回答后解析为折线、柱状或饼图；只接受经过校验的标题、标签和数值，不执行模型输出的 HTML 或额外图表配置。图表有可展开的数据表格；解析失败保留原文。
- 发送失败时保留问题并显示错误；“重新填入问题”仅把文字放回输入框，不会自动重试，避免网络结果不确定时重复提交。
- 支持在当前页面新建、切换、删除多个会话。删除会话会调用后端接口清理记忆并失效该会话旧回答缓存；后端不可用时保留本地会话，不假装删除成功。
- 当前对话只保存在内存；刷新页面会丢失页面消息并要求重新登录。后端已有持久化会话记忆，但尚无会话列表/读取接口供前端恢复，也不支持跨设备同步。
- 登录响应只有 `token`、`username`、`role`，暂不显示具体大区名称。
- 系统管理员登录后进入 `/admin`，仅管理账号，不可进入销售问答；销售用户可从工作台进入 `/change-password` 自行修改密码。管理员初始账号由后端环境变量一次性创建，详见后端 README；没有开放自助注册。
- 后端回答缓存 Key 已加入用户 ID 和会话代数，且只对同会话连续重复的问题命中；会话清空后不再命中旧回答。SSE 跨线程工具身份已在隔离联调服务上验证；切换到正常服务前仍须重启后端加载新代码。

## 回归验收

自动化：`npm run test` 覆盖 SSE 分片/中断、三类图表解析、非法图表回退、本地会话切换与清除、认证请求；`npm run build` 验证类型检查和产物构建。后端已运行 `mvn test`；详见根目录的联调验收记录。

手工联调清单（需后端和 MySQL/Redis/模型服务在线，不能由单测代替）：

1. 分别用销售员、主管、总监账号登录，检查推荐问题及越权查询拒绝；退出后换账号，确认前一个账号的本地会话不再出现。
2. 分别在同步、流式模式询问销售额，再问折线、柱状、饼图；确认图表可见、数据表数值与回答一致、没有 `CHART_JSON` 残留。
3. 模拟 SSE 中断或服务异常：未收到 `done` 时显示失败，不把半截回答渲染成图表。
4. 连续新建两段会话并切换；删除其中一段后，以相同问题重问，确认后端不会返回清空前的缓存回答。
5. 刷新浏览器确认需重新登录且本地会话不恢复；在网络不可用时删除会话，确认页面报错且本地会话保留。
