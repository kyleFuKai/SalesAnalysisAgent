# 智能销售数据分析 Agent｜前端产品与交互设计 v1.0

> 状态：设计稿，尚未实现。依据：业务需求、现有技术架构、2026-10-02 后端代码，以及对话工作台 / 经营驾驶舱 / 极简提问页三张概念图。概念图中的金额、日期、完成率等均为视觉示例，不是系统真实数据。

原型图：[A 对话工作台](./原型-A-对话工作台.png) · [B 经营驾驶舱](./原型-B-经营驾驶舱.png) · [C 极简提问页](./原型-C-极简提问页.png)。

## 1. 现状与设计选择

`04.前端实现` 此前没有页面代码或独立前端设计。技术架构文档已选 Vue 3、SSE、ECharts，但没有规定页面、交互及接口契约。

采用 **A 对话工作台为主界面**：贴近“普通销售自然语言问数”的核心价值。吸收 C 的极简提问入口与推荐问题；B 的经营驾驶舱只作为后续阶段的总监/主管视图，不在首版伪造实时指标。桌面优先，同时保证窄屏可用。

设计原则：先问后看、按角色展示、安全边界明确、所有数据有来源与时间范围、异常与错误能被用户理解。前端的权限显示只改善体验，真正的数据隔离始终由后端负责。

## 2. 用户、导航与信息架构

| 角色 | 默认入口 | 可见能力 | 不展示的入口 |
| --- | --- | --- | --- |
| 销售员 `SALES_REP` | 我的销售问答 | 本人订单、业绩、趋势、图表、本人异常 | 他人/大区/全公司排名与汇总 |
| 主管 `SALES_MANAGER` | 大区销售问答 | 本区订单、人员排名、品类/产品、趋势、本区异常 | 其他大区与全公司横向对比 |
| 总监 `SALES_DIRECTOR` | 全公司销售问答 | 全公司问答、各区排名与占比、异常 | 无角色限制的业务视图 |

首版导航：`智能问答`、`会话`、右上角 `当前用户 / 角色 / 数据范围 / 退出登录`。`经营概览`、`异常预警`可先做为**问答快捷入口**，点击填入预设问题，不冒充已有独立报表接口。不要显示与当前角色不匹配的推荐问题。未经后端确认，不显示“目标完成率”“客单价”“客户数”“数据刷新时间”等概念图里的占位指标。

## 3. 页面设计

### 3.1 登录页 `/login`

标题、简短产品说明、销售员 ID、密码、登录按钮。当前后端使用 `repId + password`，不是用户名/邮箱登录。输入错误只显示后端统一提示“账号或密码错误”；加载时禁用重复提交。不要在正式页面列出测试账户或默认密码。

### 3.2 智能问答页 `/chat`

布局采用三栏：左侧会话导航，中间对话，右侧身份范围与推荐问题。窄屏时右栏折叠到抽屉，输入框固定在可视区底部。

- 空状态：一句“今天想了解什么销售数据？”，按角色显示 3–4 个真实可问的问题。
- 提问框：最多 2000 字；回车发送、Shift+Enter 换行；正在生成时防重复提交，提供“停止显示”操作，但要标注当前后端不支持取消模型执行。
- 回答卡：文本、表格、ECharts 图表三种内容区域；显示提问时间、涉及的时间范围和可见的数据权限。没有后端来源字段时，不显示精确“数据更新时间”。
- 权限提示：如“仅查看本人数据 / 仅华东区数据 / 全公司数据”；这是登录身份说明，不代替服务端鉴权。
- 错误状态：未登录、无权限、限流、服务错误、SSE 中断分别提示；不要把异常堆栈或敏感参数展示到页面。
- 推荐问题：销售员“我本月卖了多少”“近 30 天我的订单”“我的销售趋势”；主管“本区本月销售额”“本区 Top 5 销售员”“本区有什么异常”；总监“各大区销售额排名”“近半年销售趋势”“最近有什么异常”。“完成率”要等目标数据及计算接口真正具备后再推荐。

### 3.3 会话页 `/sessions`（首版仅本地会话）

新建会话、切换本机保存的会话 ID、清空当前会话。会话 ID 用 UUID 生成；前端保存最小会话元数据与可选本地消息快照，并按当前登录用户隔离。现有后端**没有会话列表或读取历史接口**，因此跨浏览器/设备恢复历史不能承诺；清空本地记录与调用后端 `DELETE /agent/session/{sessionId}` 要分别处理。退出登录时清除前端敏感状态。

### 3.4 经营驾驶舱 `/overview`（后续）

对应原型 B，但暂不接静态假数据。需新增结构化 KPI/排名/趋势/预警接口或明确由问答接口驱动。角色视图：销售员仅本人、主管仅本区、总监全公司。完成率还需要销售目标数据表或口径，不能凭已有订单表推算。

## 4. 接口契约（按当前后端代码）

| 场景 | 请求 | 当前响应 / 注意事项 |
| --- | --- | --- |
| 登录 | `POST /auth/login`，JSON `{ "repId": 2, "password": "…" }` | `{ "token", "username", "role" }`；登录响应不含 regionId / repId；大区名若要精确显示，需新增“当前用户信息”接口。 |
| 退出 | `POST /auth/logout` | 成功后删除前端 token 与本地敏感会话状态。 |
| 同步问答 | `POST /agent/chat`，JSON `{ "sessionId", "message" }` | `{ "sessionId", "reply", "durationMs" }`。 |
| 流式问答 | `POST /agent/chat/stream`，同样的 JSON | `text/event-stream`；`token` 事件数据为文字片段，`done` 数据为 `[DONE]`，`error` 为用户可见的失败提示。 |
| 清会话 | `DELETE /agent/session/{sessionId}` | 空响应；当前只清后端消息存储，回答缓存可能仍命中，前端不能保证重复提问重新计算。 |

认证头按实际 `sa-token.token-name` 配置发送；不要把 token 放到 URL。当前流式接口是 **POST + JSON + 鉴权头**，原生 `EventSource` 只支持 GET，前端应使用 `fetch` 读取 `ReadableStream` 并解析 SSE。解析要处理 UTF-8 跨 chunk、一个 chunk 多事件、CRLF、空行分隔和网络断流；`done` 后才标记成功。首次可用版本允许切换同步问答作为降级，但不能把流式失败静默当成功。

后端错误体目前并不统一：登录错误为 `{ "error": "…" }`，大多数全局异常为纯文本；前端网络层需兼容两种形式。401 清 token 并跳登录；403 显示权限原因；429 显示稍后重试；5xx 显示通用错误及重试。SSE 已开始后的错误从 `error` 事件获得，不再依赖 HTTP 状态。

## 5. 图表协议与安全显示

当前图表工具返回 `CHART_JSON:` 加 ECharts `option` JSON，模型再把它写到回答中。前端需从完整回答里定位此前缀，**等待完整 JSON 后**解析并渲染，同时将其从普通文字区移除。SSE token 可能把前缀与 JSON 拆成多片，因此不要逐片解析。解析失败时保留用户能读懂的解释，并显示“图表暂时无法展示”；不要执行 JSON 中的代码或任意脚本。

ECharts 只接受白名单图表类型（line/bar/pie）与有限字段，过滤危险 HTML formatter / 函数形式配置；回答 Markdown 也要进行 HTML 净化，不能直接 `v-html` 原始模型输出。金额和时间范围由后端数据决定，前端不自行编造同比、环比或异常结论。

## 6. 前端工程建议

技术栈：Vue 3 + TypeScript + Vite + Vue Router + Pinia + ECharts。样式先用少量设计 token 和组件化 CSS；不急着引入重型 BI 组件库。目录建议：`src/views/{LoginView,ChatView,SessionsView}.vue`、`src/components/chat/`、`src/components/chart/`、`src/api/{auth,agent,sse}.ts`、`src/stores/{auth,chat}.ts`、`src/router/`、`src/styles/`。

视觉沿用原型 A：浅色底、深蓝文字、蓝绿强调；单列对话的最大宽度约 900 px，右栏约 280–320 px。异常用琥珀色，错误用红色，避免只靠颜色表达状态。金额突出但图表标题、单位、时间窗口不可省略。桌面宽度不足时先收起右栏，再收起左栏。

Token 保存优先采用内存态；刷新后需重登是首版可接受的安全取舍。若产品要求刷新保留登录，需要另定同源部署、Cookie/持久化策略和 XSS 防护。Vite 开发代理把 `/auth`、`/agent` 转发至后端，减少本地跨域配置；实际后端端口以运行环境为准，不把示意端口写死在组件里。环境变量只放非敏感 API base URL，不放密钥。

## 7. 里程碑与验收

1. **MVP**：登录、退出、角色提示、问答（同步 + POST SSE）、流式状态、会话 ID 管理、错误处理、图表显示。用真实接口验证普通销售/主管/总监三种身份。
2. **增强**：本地会话列表、推荐问题、复制回答、图表下载、移动端适配、无障碍键盘操作。
3. **后端接口齐备后**：跨设备历史会话、用户详情、结构化经营驾驶舱、真实目标完成率、异常列表。

验收重点：销售员不能通过 UI 推荐或接口参数看到他人数据；主管不显示跨区入口；同一会话连续提问能关联上下文；SSE 断流不误报成功；图表 JSON 分片与解析失败均有兜底；401/403/429/5xx 行为可区分；页面不含演示数字或测试账号。

## 8. 已知后端阻塞项

- 当前 `app.auth.enabled: false` 时拦截器不写 `UserContext`，而 Agent Controller 要求身份，正常前端问答需要开启认证或修正开发环境链路。
- 回答缓存 key 未包含 userId，存在同角色/同区用户共享同 sessionId 时串回答风险；前端使用随机 UUID 只能降低碰撞，不能代替后端修复。
- 流式工具执行可能丢失 ThreadLocal 用户身份，需先做真实 SSE 权限回归测试。
- 清会话只删持久记忆、不清回答缓存；缓存命中也不会向 ChatMemory 追加新轮次。前端要如实提示，不承诺清空后立即重算。
- 无当前用户详情、会话列表/读取、独立 KPI/目标接口；对应页面先保持设计状态，不以静态数据冒充真实业务。
