# 智能销售数据分析 Agent｜前端开发分步计划 v1.0

> 配套设计：[前端产品与交互设计 v1.0](./前端产品与交互设计-v1.0.md)。本文件只规划开发顺序和验收点，不代表这些页面已经实现。首版以原型 A 为主体，吸收原型 C 的快捷提问；原型 B 留到结构化接口具备后。

## 开发顺序总览

`0 联调前提 → 1 工程骨架 → 2 登录鉴权 → 3 问答静态布局 → 4 同步问答 → 5 流式问答 → 6 图表 → 7 会话与角色体验 → 8 回归验收 → 9 经营驾驶舱（后续）`

每一步完成并手动验收后再进入下一步；先保证能登录、能问、能读懂错误，再做视觉与高级功能。开发代码放在 `04.前端实现` 下独立前端工程目录，不与设计文档、原型图混放。

## 0. 联调前提：先让“带身份的问答”走通

当前后端 `app.auth.enabled: false` 时不向 `UserContext` 写入身份，而 `/agent/chat` 又必须有身份；这会让前端登录后仍无法问答。先由后端确定联调配置：开启认证，验证 `POST /auth/login` → 带 `Authorization` 请求头调用 `/agent/chat` 可成功。不要在前端伪造用户上下文，也不要为开发方便绕过后端权限。

同一步确认后端实际端口、前端开发代理路径、三种测试角色的登录方式；修复或记录当前回答缓存可能串用户、流式跨线程上下文风险。这些属于后端联调前提，不计作前端功能。

**验收**：销售员、主管、总监各能登录并得到权限范围内的同步回答；401/403 能按预期返回；前端测试不依赖硬编码密码。

## 1. 工程骨架与设计基础

创建 Vue 3 + TypeScript + Vite 工程，接入 Vue Router、Pinia、ECharts。建立 `src/views`、`src/components`、`src/api`、`src/stores`、`src/router`、`src/styles`。配置开发代理和非敏感 API 地址；定义颜色、字号、间距、阴影等基础 token。页面先建 `/login`、`/chat` 两个空路由和 404 页。

**验收**：本地启动、刷新路由不白屏、构建无 TypeScript 错误；没有把数据库/模型密钥或后端密码放进前端环境变量。

## 2. 登录与请求基础层

实现登录表单（`repId + password`）、登录态 store、退出登录、路由守卫和统一请求封装。登录响应只有 `token`、`username`、`role`，不假定有大区名。请求头名称以现有 Sa-Token 配置 `Authorization` 为准；令牌先存在内存中，刷新后重新登录。统一处理两种错误体：登录的 JSON `{error}` 与其他接口的纯文本。

**验收**：登录成功能进入问答页；密码错误提示正确；无 token 不能访问问答；401 清除前端登录态并跳登录；退出后无法沿用旧页面发请求；不在地址栏、日志、页面展示 token。

## 3. 问答页静态布局（不接假业务数据）

实现原型 A 的三栏结构：左栏会话导航、中栏消息区与底部输入、右栏身份说明与示例问题。空态借鉴原型 C。先用组件级静态文案调布局，**不放示例销售额、完成率、排名和预警数据**。组件建议：`AppShell`、`ConversationList`、`MessageList`、`MessageCard`、`ChatComposer`、`IdentityPanel`、`PromptSuggestions`。

**验收**：三种角色显示对应的权限文案和推荐问题；销售员界面没有跨区问题入口；窄屏可折叠侧栏；输入框支持回车发送、Shift+Enter 换行并校验 2000 字上限。

## 4. 同步问答 MVP

封装 `POST /agent/chat`，请求 `{sessionId, message}`，用 UUID 为新会话生成 `sessionId`，同一会话后续提问复用它。消息状态至少包括“待发送、发送中、成功、失败”。先实现纯文字回复、错误提示、重试入口；不要从模型文字里自行计算业务指标。

**验收**：一轮成功问答与同会话追问均可完成；400/401/403/429/5xx 分别给出可理解的提示；发送中不会重复触发请求；失败不会误标成已回答；切换会话后消息不会串到其他会话。

## 5. POST SSE 流式问答

封装 `POST /agent/chat/stream`：使用 `fetch + ReadableStream`，不用原生 `EventSource`（它无法按当前接口要求发送 POST JSON）。实现 SSE 解析器：处理跨 chunk 的 UTF-8、一个 chunk 多事件、空行分隔、`token/done/error` 事件。只有收到 `done` 才标记成功；网络中断显示“回答中断，可重试”。可提供同步接口作为显式降级。

**验收**：文字逐步出现，末尾无重复片段；缓存命中返回单个大 `token` 也能正确显示；`error` 事件及中途断开不会当作成功；关闭/离开页面后不继续往旧组件写消息。实际业务工具调用的 SSE 测试需通过第 0 步所述后端身份回归。

## 6. 图表渲染

集成 ECharts。当前协议是回答文字中的 `CHART_JSON:` + JSON option；**先累积完整回复**，再识别前缀、解析 JSON、拆分普通文字与图表。只接受 line/bar/pie 等当前工具实际生成的图表类型；禁止执行任意 formatter 函数或直接注入 HTML。解析失败时保留文字说明和明确的图表失败提示。组件建议：`ChartMessage.vue` + `chartParser.ts`。

**验收**：折线、柱状、饼图各一条真实问答能显示；SSE 把 `CHART_JSON:` 拆在多个片段时仍能解析；JSON 不完整或格式不对不导致页面崩溃；图表标注单位和时间范围。图中的数据必须来自后端回答，不使用原型图示例数值。

## 7. 会话与角色体验

本地管理会话 ID、标题及本机消息快照；支持新建、切换、清空当前会话。清空时调用 `DELETE /agent/session/{sessionId}`，并清理本机对应记录。由于后端尚无会话列表/读取接口，不承诺换浏览器或换设备恢复历史。不同用户的本地会话必须分开，退出时清除敏感状态。推荐问题点击后只填入或发送问答，不调用测试工具接口。

**验收**：新建会话不继承上一个会话的上下文；切换会话内容不串；同一浏览器换账户看不到前一账户的本地内容；清会话失败时给出提示。后端目前不清回答缓存，清空后“同题一定重算”不作为前端承诺，需等后端修复。

## 8. 回归、可用性与交付

写单元测试覆盖请求错误归一化、角色推荐问题、SSE 解析器、`CHART_JSON` 解析器；用三种角色做真实接口联调。检查 XSS：模型回答若支持 Markdown，渲染前必须净化 HTML；不要直接 `v-html` 原始内容。检查键盘操作、加载状态、窄屏布局和空数据提示。

**验收**：能复现并通过“销售员问他人/主管问外区/总监问全公司”的权限用例；同步和 SSE 均可正常问答；无控制台未处理异常；`npm run build` 与测试通过；README 写清本地启动、联调配置与已知限制。

## 9. 第二阶段：经营驾驶舱（暂不开发）

原型 B 中的 KPI 卡、区域排名、Top 产品、异常列表需要结构化接口和稳定指标口径；“完成率”还缺销售目标数据支撑。等后端提供当前用户详情、会话读取/列表、结构化统计和目标数据后，再设计 `/overview` 及主管/总监差异化布局。首版不要靠解析自由文本拼仪表盘，也不要用静态演示数据冒充实时数据。

## 推荐实施节奏

第一次写代码只做 **第 0–2 步**，确认登录与权限链路；第二次做 **第 3–4 步**，形成最小可用问答；第三次做 **第 5–6 步**，解决流式与图表；最后做 **第 7–8 步**，完成会话和质量收尾。每阶段都能独立验证，避免一次改动过多难以定位问题。
